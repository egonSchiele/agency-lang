# `agency eval edit` — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `agency eval edit <test-dir>` opens an existing test in the `eval new` form, loaded from `test.json` and `graders.json`, and saves both back in place without touching anything else in the folder.

**Architecture:** The form gains one optional piece of state, `editing`: the folder being edited, the parsed `test.json` to write fields back over, and a snapshot of what was loaded. Two rows and the graders section can be locked, each with the text shown in its place. A new pure module, `load.ts`, turns a test folder into a form state and refuses the folders the form cannot edit. The write, in edit mode, builds both files in the staging folder and moves them over the originals one file at a time. The command is a second entry point over the same screen loop.

**Tech Stack:** TypeScript, vitest, the TUI toolkit in `lib/tui/`.

**Spec:** `docs/superpowers/specs/2026-10-20-graders-as-data-and-eval-edit-design.md`, Part 3. Linear: ADI-31. Depends on ADI-30 (plan `2026-10-21-eval-new-graders-section.md`) being merged: this plan reads `Row`, `GraderDraft`, `draftFromSpec`, `specObjectFor`, and `rowsOf` from it, and the "graders.ts" lock is a lock on the section that plan adds.

## Background

Read `docs/dev/evals/eval-new.md` after ADI-30 lands; the plan for ADI-30 has a Background section that describes the form as it is today. What this plan adds on top:

After ADI-30, `FormState` holds `suiteDir`, `values` for the five fields, `graders: GraderDraft[]`, a `Row` cursor, a `mode`, a footer `message`, `scrollTop`, `done`, and `written`. `rowsOf(state)` lists every row the cursor can visit. `validateForm` checks the five fields and every grader, and `writeTest` builds `<suite>/.staging-<id>/` with `test.json` and, when there are graders, `graders.json`, then renames the folder to `<suite>/<id>/`. `testJsonFor(values)` is the object `test.json` holds: `description`, `input`, `goal`, each only when non-empty.

The loader (`loadTestDir` in `lib/eval/loadInputs.ts:138`) reads a test folder's `test.json` as a plain object, defaults `id` to the folder name, and discovers `files/`, `graders.ts` or `graders.json`, and `graderFiles/` beside it. A `test.json` may carry keys the form never shows: `tags`, `timeoutSec`, `expected`, `metadata`, `harnessMaxCost`, `harnessMustPass`, and `input` may be an object rather than a string (`loadInputs.ts:238`). `parseGradersJson(text, filePath)` in `lib/eval/gradersJson/schema.ts` reads a `graders.json` into `GraderSpec[]`, and ADI-30's `draftFromSpec` turns one spec into the form's draft.

`safeDeleteFile` and `safeDeleteDirectory` in `lib/utils.ts` refuse any path outside the nearest `package.json`, so a suite under `os.tmpdir()`, where every test here builds one, is refused by them; `safeDeleteDirectoryWithin(root, target)` takes the boundary as an argument instead, and the staging code already uses it. `walkTreeRefusingSymlinks(dir, what)` in `lib/eval/grading/graderFilesSnapshot.ts:50` lists the files under a directory and throws on a symlink.

## Global Constraints

- The folder name row cannot be changed. Renaming a test is moving a folder.
- The files row cannot be changed. It reads `files/ (12 files)` or `none`.
- Save writes `test.json` and `graders.json` back in place, through the staged folder, and leaves everything else in the folder alone.
- Removing every grader deletes `graders.json` rather than writing `[]`.
- Keys in `test.json` the form does not show are kept. The form keeps the parsed object and writes its fields over it. Opening a hand-written test in the form never loses a key.
- A test with `graders.ts` opens with the graders section reading `graders.ts: edit the file` and no grader rows. The rest of the form works.
- A test whose folder name differs from its `id` in `test.json` is refused with a message.
- Run `pnpm run typecheck` after every edit. Save test output to a file. Format with `pnpm run fmt:ts` before committing. Do not run the full agency test suite locally.
- No `Map`, no `Set`, no `interface`, no dynamic import, no `...(x ? { x } : {})` spread, no one-line `if`, no magic numbers; every delete through a `safeDelete*` helper with `dryRun` false. Read `docs/dev/contributing/anti-patterns.md` before each task.

## Review Focus

- A `test.json` whose `input` is an object (structured input) must open with the input row locked, reading `structured input: edit the file`, and be written back unchanged. Pinned in Tasks 2 and 3.
- Clearing a field that was set (`description` emptied) must remove the key from `test.json`, not write `""`, because the loader refuses an empty `input` string. Pinned in Task 3.
- A save that fails after the question (the folder vanished, `graders.json` became a directory) must leave the originals as they were and return to the form with the problem. Pinned in Task 3.
- Quitting an unchanged test must not ask "discard this test?": `isDirty` compares with what was loaded, not with empty. Pinned in Task 1.
- A test folder with a `files/` directory holding a symlink must still open, with the files row reading a count that says it could not be read, since the form never copies files in edit mode. Pinned in Task 2.

### Task 2: A test folder becomes a form

**Files:**
- Create: `lib/eval/newTest/load.ts`
- Test: `lib/eval/newTest/load.test.ts`

**Interfaces:**
- Consumes: `editingForm` from Task 1; `loadInputs` from `lib/eval/loadInputs.ts`; `parseGradersJson` from `lib/eval/gradersJson/schema.ts`; `draftFromSpec` from `lib/eval/newTest/graders.ts`; `walkTreeRefusingSymlinks`.
- Produces:
  - `loadTestForm(testDir: string): FormState`. The loader already knows what a test folder is, so this function asks it first: `loadInputs(testDir)` gives one `Test` or throws the loader's own message (not a directory, no `test.json`, not an object, both grader files, a bad `input`). Every refusal the loader makes, this function inherits without a line of its own. Two checks are the form's: the folder must hold exactly one test (`loadInputs` of a folder with no `test.json` would read it as a suite, so check `test.json` exists first and throw `${testDir} has no test.json; eval edit opens one test folder`), and the raw `id` must match the folder (`${testDir}/test.json names id "${id}" but the folder is "${basename}"; rename the folder or the id`).
  - Values from the `Test`: `description` and `goal` as given or `""`; `input` when it is a string. When `test.input` is an object: `""` and a lock on `input` reading `structured input: edit the file`. A `base.rubric` is refused at load with `${testDir}/test.json has a rubric; this form edits goal`, since the loader refuses a goal beside a rubric and the form would write one.
  - Locks: `id` always, reading the folder name. `files` always: when `base.files` is a string the lock shows that string (the loader honours any directory, and the form models only the sibling `files/`); otherwise `files/ (${n} files)` when `test.files` is set and holds `n` files, `none` when it is not set. The count comes from `walkTreeRefusingSymlinks` after an `lstat` of the folder itself, as `snapshotGraderFiles` does, since `readdirSync` follows a link at the root; either refusal reads `files/ (could not be read: ${message})`.
  - Graders from `test.graders`: when it is `<testDir>/graders.json`, the file is read with `parseGradersJson` and `draftFromSpec` per spec (a parse error is thrown as is; the message names the file). Any other path, a `graders.ts` beside the test or a path `base.graders` named elsewhere, sets `gradersLock` to `${path relative to testDir}: edit the file` and no drafts, because a `graders.json` the form wrote would be ignored while `graders` points elsewhere. No `graders` means no graders. The both-files refusal is the loader's.
  - `base` is the raw `test.json` object, read once for the keys the form never shows, and kept whole: an `id` the file spells out is written back as it was, and a file with no `id` never gains one, because `testJsonFor` writes only `description`, `input`, and `goal` over the base.

### Task 3: Writing back in place

**Files:**
- Modify: `lib/eval/newTest/write.ts`
- Test: `lib/eval/newTest/write.test.ts`

**Interfaces:**
- Consumes: `Editing` from Task 1.
- Produces:
  - `testJsonFor(values: Record<FieldName, string>, base: Record<string, unknown> = {}): Record<string, unknown>`: `base` with `description`, `input`, `goal` set from `values` when non-empty and deleted when empty. A locked `input` (structured) is not in `values` as text: the caller passes `values` whose `input` is `""`, and the key must survive, so `testJsonFor` skips a field that is locked. Make that explicit: the signature takes `locks: FormState["locks"]` as a third argument, and a locked field is left as `base` has it.
  - `validateForm(state, checks)`: a locked field is not validated. That one rule, read from `state.locks`, is what skips the `id` checks (required, pattern, exists) in edit mode; `validateForm` never asks whether the form is editing.
  - `writeTest(state)` keeps one shape for both modes. The "what" is `stagedFiles(state): { name: string; text: string }[]`: `test.json` from `testJsonFor(values, base, locks)` (an empty `base` when creating) and, when there are graders, `graders.json`. The "how" is: remove a stale staging folder, make it, write every staged file into it, then `COMMITS[mode](staging, state)`, then remove the staging folder in a `finally`. `COMMITS` is a two-entry table keyed by `"create" | "replace"` (`"replace"` when `state.editing` is set):
    - `create`: copy the files directory when one was typed, check the target does not exist, and rename the folder into place, as today.
    - `replace`: first, for each target the commit will touch (`<testDir>/test.json`, `<testDir>/graders.json`), check with `lstat` that it is absent or a regular file and not a symlink, and throw a `TestWriteError` on the goal row otherwise, before anything moves. Then, when there are no graders and `<testDir>/graders.json` exists, `fs.renameSync` it into the staging folder, so it leaves with the staging folder rather than through a delete helper (`safeDeleteFile` refuses a path outside the nearest package, which every temp-dir suite is). Then `fs.renameSync` each staged file over its target, each a one-step replacement.
    Any error before the renames leaves the originals as they were; the checks make a failure between the two renames a race the form cannot close, and the message then says which file was written. Returns the test folder.
  - `nextCommands(suiteDir, id)` is reused by the edit command's summary, so it needs no change.
