# Stdlib developer docs

Paths are relative to `packages/agency-lang/`. Read the one that matches the task; each doc records the key decisions, the architecture, the relevant files, and the subtleties that are easy to miss.

- `docs/dev/stdlib/adding-a-module-to-the-agency-stdlib.md` — The pattern for adding a stdlib module, including where files go and how docs are generated.
- `docs/dev/stdlib/agency-function-tools.md` — `runFunction` and `learn`: prepared subprocess calls, metadata inspection, ordinary callable behavior, and the coordinator's session records.
- `docs/dev/stdlib/data-connectors.md` — Writing a `std::data` connector that reads a public data source, and the conventions they all follow.
- `docs/dev/stdlib/asking-the-user.md` — `question` and the `std::question` effect: why asking goes through an interrupt, why no policy rule can answer it, which agents carry the tool and which are handed it at the call site, and the prompt hint without which none of them use it.
- `docs/dev/stdlib/aws.md` — S3 support with no AWS SDK, including the request signer and the safety contracts around it.
- `docs/dev/stdlib/contained-files.md` — The file part of the host, which every stdlib file operation goes through: the root that is realpathed once, the refusal of any symlink below it, the whole-path split, how a helper gets the host, the lint fence, and the symlink battery.
- `docs/dev/stdlib/fetch-cache.md` — The per-run fetch cache: why a model tool call that GETs a URL the same conversation already fetched gets the stored result and not a note pointing at it, why the agent toolkits bind `refresh`, the one key for every spelling of a URL, why only a tool call, only a GET, and only the same thread lineage are cached, why a hit raises no interrupt, why it lives in the run's globals, and the 500,000-character cap.
- `docs/dev/stdlib/http-timeout.md` — The 30-second limit on `std::http` fetches: one signal for headers and body, why a timeout is a `Failure` and a cancel is not, the `0` meaning no limit, and which fetch callers are still unlimited.
- `docs/dev/stdlib/ui-layout-widths.md` — How wide a `std::ui/table` is: the limit from the terminal or the container, which columns shrink and to what width, the raw-cell exception, why `fitColumnWidths` is kept apart from the TUI table's column code, and the cap on `diff()`'s colored bars.
- `docs/dev/stdlib/grep-flags.md` — `std::grep`: why it is an in-process regex walk and not the `grep` program, the flag rule table that turns grep habits into regex flags or named parameters, the messages a rejected flag sends back to the model, and the path table: `path` with `dir` as its alias, a file searched alone, and the one check `ls`, `grep`, and `glob` run before their interrupt so a missing path or a file given to `ls` fails with a message for the model instead of an empty success.
- `docs/dev/stdlib/safe-bash.md` — `safeBash`: the plan-then-act model (`planFor` decides, nothing runs inside it), the five rules (truthful payloads, all or nothing, rebuilt text when narrow, every shell spawn raises an effect, approval of the question not the bytes), the three outcomes and `outcomeOf`, `Plan.broadReason` with its four kinds and `Plan.verbs`, the `safeBash plan` debug event and how to tally a session, the sentence table behind a rejected broad command, the two greps and when a lone grep runs the tool's search, the pipe flag on `FlatCommand` and `stdinStage` as the one place that reads it, and why the executors call `_bash`, `_write`, and `_grep`.
- `docs/dev/stdlib/embedding.md` — `std::embedding`: `embed` and `embedMany` over the active client, the metered accounting order copied from `std::image`, why the branch token counter uses the projected total, and why there is no interrupt.
- `docs/dev/stdlib/github.md` — `std::github`: why it speaks REST directly, the three-source credential chain, why the token never becomes an Agency value, and the deliberate departures in its effect vocabulary.
- `docs/dev/stdlib/ocr.md` — `std::ocr` and `viewFile`: the three effects and why they are separate, the before/after-approval split and where each function reads its bytes, the osascript bridge with a temp copy, the Vision y flip, why local never falls back to cloud, and why `viewFile` says "queued".
- `docs/dev/stdlib/skills-write.md` — The `std::skills` write half: writeSkill's save gate, designSkill's review-and-redraft loop over it, the subdir scan's path-segment validation, and the frontmatter round-trip contract.
- `docs/dev/stdlib/spill.md` — `std::spill`: long tool output kept in the run's globals beside the fetch cache, so it is per run and rides in every checkpoint; the two name-only tools that read it back, found by module and registered name, and which agents carry them; the cap, bounded by the hosted resume limit, and the "no longer available" rule; the two `llm()` options that decide what happens to a long tool result (`maxToolResultChars` as a ceiling, `spillToolResultsOver` to save), why the tool list never changes it, and why the option is per call; why an object result is saved indented; and why there are no effects.
- `docs/dev/stdlib/std-agency-test.md` — `test()` and `testFile()` from `std::agency`, and the sandbox rules that are easy to get wrong.
- `docs/dev/stdlib/toolbox.md` — `std::toolbox`: tools an agent writes and keeps; the tool template, the designTool pipeline and the plain writeTool, the save gate both publish through, and runTool.
- `docs/dev/stdlib/workflow.md` — `std::workflow`: a JSON step list compiled to an Agency program through parse, resolve, lower, and render; the three doors workflow text enters by, why the scaffold is fixed text and the naming rules that keep template hygiene from renaming a binder, why return types come from `describe` and the check for a plain return, which return types warn, why every refused tool is reported at once, `Inputs!` on `main`, a context value as text or JSON, why an LLM step is a `let` assigned inside its `thread` block, `runWorkflow` as check, ask, run, how a step's interrupt pauses and resumes the child, step limits as a guard named after the step with `holdsResult` deciding `.value`, one local per argument, the line ranges from per-fragment prints, the payload rule for diagnostics, and saving and loading under `<dir>/workflows`.
