# `async` — Implementation Plan

**Goal:** `async f()` and `let x = async f()` run `f` beside the statements
that follow, joined at the first use of `x` or the end of the block, by
lowering to a `parallel` block. Two runtime changes: one fork arm can keep
the conversation thread, and a handler applies only inside the branch that
registered it. The old `async` runtime (pending promises, drained at four
boundaries) is deleted in a separate change.

**Keyword (decided 2026-11-04):** the construct was first drafted as
`spawn`, then `parallel` as a prefix. `spawn` promises a detached task,
which this is not, and would reserve a new word that collides with
`node:child_process`. `parallel` as a prefix reads as a one-arm block in
value position, which is a different thing, and the thought experiment in
the review conversation showed that confusion would be routine. `async`
already has this exact surface in the language, is already reserved, and
its only cost is the "pair with `await`" connotation from other languages.
Old `async` programs keep compiling and get the new semantics, which are a
superset of the old ones.

**Spec:** `docs/superpowers/specs/2026-11-04-spawn.md` (file name kept; the
spec says `spawn` throughout and needs the rename, see "Spec edits"). Notes
and spike results: `docs/dev/language/fire-and-forget-notes.md`. Spike
branch `spawn-spike`, commit `24541aa12`, worktree `worktrees/spawn-spike`.
Reviews of the earlier drafts of this plan, both in
`worktrees/spawn-spike/packages/agency-lang/docs/superpowers/plans/`:
`2026-11-04-spawn-review.md` and `2026-11-04-spawn-review-2.md`.

**Tech stack:** parser in `lib/parsers/parsers.ts`, AST types in
`lib/types/`, lowering in `lib/preprocessors/parallelDesugar.ts` and
`typescriptPreprocessor.ts`, typechecker in `lib/typeChecker/`, runtime in
`lib/runtime/runBatch.ts`, `runner.ts`, `interrupts.ts`,
`agencyFunction.ts`, `agency.ts`, and `state/context.ts`, builder in
`lib/backends/typescriptBuilder.ts`. Fixtures under `tests/agency/async/`
and `tests/agency-js/async-*`.

## Background

- `parallel { }` is desugared by `desugarParallelInBody`
  (`lib/preprocessors/parallelDesugar.ts`), called from
  `desugarParallelBlocks` in `typescriptPreprocessor.ts:396` for every
  function and node body. It validates the arm allowlist
  (`ALLOWED_ARM_TYPES`, line 55: `assignment`, `functionCall`,
  `valueAccess`, `seqBlock`, `parallelBlock`, comments; NOT
  `withModifier`), computes `collectBindings` and `collectReferences` per
  arm, rejects cross-arm references, and emits `fork([...arm names]) as
  __arm_n { if-chain }` plus one `let X = __arms_n[i].X` per hoisted
  binding. Each arm ends with `return { bindings }`. The design is in
  `docs/dev/language/parallel-blocks.md`.
- `desugarOneParallel` (`parallelDesugar.ts:485`) picks the `__arms_n`
  suffix itself with `nextSuffix()` while it runs, and returns
  `[let __arms_n = fork(...), let X = __arms_n[i].X, ...]` in place of the
  one `parallelBlock` statement. No earlier pass knows the name, and
  anything an earlier pass puts after the `parallelBlock` lands after every
  hoist.
- `collectReferences` is a hand-written switch (`parallelDesugar.ts:188`)
  with cases for `variableName`, `assignment`, `functionCall`,
  `binOpExpression`, `valueAccess`, arrays, objects, strings, `ifElse`,
  the two loops, `returnStatement`, `seqBlock`, `parallelBlock`,
  `messageThread`, and `handleBlock`. Everything else falls through to
  `default: return`: `withModifier`, `matchBlock`, `castExpression`,
  `comprehension`, `interruptStatement`, `isExpression`,
  `typeTestExpression`, `tryExpression`, `newExpression`, `gotoStatement`,
  `nodeCall`. Verified on `main`: a `seq` arm reading a sibling arm's
  binding inside `print(x) with approve` compiles and prints `undefined`
  with no cross-arm error. `lib/utils/identifierSlots.ts` is the complete
  table of identifier positions; its registry is a
  `Record<AgencyNode["type"], …>`, so a new node kind fails to compile
  until it is registered.
- Pass order in `TypescriptPreprocessor.preprocess`
  (`typescriptPreprocessor.ts:337`): decorators, guards,
  `desugarParallelBlocks`, `hoistCallsInProgram`, `addAwaitPendingCalls`,
  `validateNoAsyncInLoops`, `resolveVariableScopes`. The hoist pass is what
  lowers the `?` operator into `if (isFailure(t)) { return t }` statements
  (`lowerUnwraps`, `hoistCalls.ts:504`). Any pass that runs before it
  cannot see those returns.
- The typechecker runs before the preprocessor. Its constructor runs only
  the decorator and guard desugars (`lib/typeChecker/index.ts:129`), so it
  sees `parallelBlock` nodes and sees the `async` flag. The editor and
  `agency tc` never run the preprocessor, so an error raised from a
  lowering pass is invisible to them. `unwrapRefusals` in
  `lib/typeChecker/unwrapChecks.ts` is the pattern for a tree-only check
  that both the checker and the compile path call;
  `positionRefusals(hoistPositions(nodes), isTarget, table, params)`
  (`lib/typeChecker/positionRefusals.ts`) already classifies global
  initialization as `outsideBodies` and a handler function as
  `handlerBody`; `checkCallbackBodyInterrupts` refuses an interrupt inside
  a callback body.
- **The `async` keyword today.** It is a flag, `async?: boolean`, on
  `FunctionCall` (`lib/types/function.ts:337` and `:371`), `ValueAccess`
  (`lib/types/access.ts:19`), and the literal (`lib/types/literals.ts:69`).
  The parser sets it in `asyncValueAccessParser` and accepts and discards
  the keyword in two more places (`parsers.ts:3669`, `:4930`, `:5907`). It
  is on the reserved-word list (`parsers.ts:284`). The formatter prints it.
  Because it is a flag on an ordinary call, every walker that sees a call
  or an assignment already sees an async one: the slot tables
  (`bodySlots`, `expressionSlots`, `identifierSlots` in `lib/utils/`), the
  symbol table, effect propagation, the capability check, and `agency
  interrupts`.
- **The old `async` runtime.** The builder emits
  `__run.ctx.pendingPromises.add(...)` for a flagged call
  (`typescriptBuilder.ts:2904`, `:2908`, `:3866`) and picks
  `createAndReturnSubthread()` as the thread for a flagged `llm()`. The
  preprocessor inserts `await __run.ctx.pendingPromises.awaitPending([...])`
  before the first use (`addAwaitPendingCalls`, `:799`) and refuses
  `async` inside loops (`validateNoAsyncInLoops`). `PendingPromiseStore`
  (`lib/runtime/state/pendingPromiseStore.ts`) is drained by `awaitAll`
  calls in `node.ts`, `interrupts.ts`, `pause.ts`, `rewind.ts`,
  `checkpoint.ts`, `runner.ts`, `context.ts`, `portable.ts`, and by
  `runHandlerChain` for the promises a handler launched. An interrupt
  raised inside an async call throws `ConcurrentInterruptError`. Docs:
  `docs/dev/runtime/async.md`, `async-behavior-checklist.md`, the
  async-prompt subthread rule in `threads.md:138`, and mentions in
  `pause.md`, `checkpointing.md`, and the debugger doc's busy-list note.
  Tests: `tests/agency-js/async/*`, `tests/agency/substeps/async-in-if`,
  `tests/agency/interrupt-in-async-branches`.
- **What changes for an existing `async` program.** The join moves from
  "first use, or the drain at node return, interrupt return,
  `checkpoint()`, and handler exit" to "first use, or the end of the
  enclosing block". An interrupt inside the call is batched and resumable
  instead of thrown. `async` inside a loop body is allowed. `async` in a
  position other than a statement or the right-hand side of `let`/`const`
  becomes an error. The changelog states all four.
- A fork arm's value is whatever the arm returned: `forkBlockSetup.mustache`
  returns `runner.haltResult`, so a user `return e` anywhere in the arm
  (including inside `if`, loops, `thread`, and `handle` bodies, since
  `Runner.handle` propagates a halt) makes `e` the arm's value in place of
  the bindings object. `goto` inside a branch crashes serialization (spike
  `goto`).
- Handlers are one list per run, `ctx.handlers`
  (`lib/runtime/state/context.ts:750`). `HandlerEntry`
  (`lib/runtime/types.ts:69`) is `{ fn, liveGuardIds }` with no record of
  the registering stack. `runHandlerChain` (`lib/runtime/interrupts.ts:275`)
  walks the whole list for every raise and skips only entries executing
  in the raising lineage. Branches share the run's context, so a `handle`
  block live in one fork arm is consulted for interrupts raised in a
  sibling arm. `tests/agency-js/handler-fork-isolation` documents this.
  The tool loop runs each tool call of a model round as a branch, so two
  tools in one round share handlers the same way.
- Every registration path lands on that list: `Runner.handle` for
  `handle` blocks and the `with` modifier in runner scopes;
  `withPushedHandler` (`lib/runtime/asyncContext.ts:401`) for TypeScript
  callers, which `AgencyFunction.preapprove()`
  (`lib/runtime/agencyFunction.ts:468`) uses to wrap every call of a
  preapproved function in an approve-everything handler, and which
  `agency.withHandler` (`lib/runtime/agency.ts:294`) uses after reading
  `currentRun()`; the `--policy` handler and the global-init wrapper
  (`withHandlerWrapper.mustache`), which have no runner stack.
- The raising stack reaches the chain through `interruptWithHandlers`
  (`interrupts.ts:640`), which reads `opts?.stack ?? run.stack`. Its
  callers: the generated `interruptReturn` and `interruptAssignment`
  templates (no stack passed; `run.stack` is the branch stack inside an
  arm, set by `runInBranchAlsFrame`), the TypeScript `interrupt()` in
  `agencyInterrupt.ts:202`, `guardTripInterrupt.ts:148`, and `ipc.ts:715`
  through `gatherChainOutcome`, which passes the stack `_run` was called
  on.
- `StateStack.parent` (`lib/runtime/state/stateStack.ts:492`) links a
  branch stack to the stack it branched from, and `branchPath()` walks it.
  It is live-only: `rehydrateInheritedGuards` (`runBatch.ts:326`) sets it
  on every entry into a branch, including re-entry after a resume, before
  the branch runs any code.
- `fork` named arguments are validated in the typechecker's builtin table
  (`lib/typeChecker/builtins.ts:453`, `acceptsNamedArgs`) and the builder
  (`typescriptBuilder.ts:3170`). The parser validates named arguments only
  for `parallel(...)` (`parsers.ts:6964`). The builder passes `shared` as
  the trailing argument of `runner.fork(...)` (`typescriptBuilder.ts:3240`).
- `Runner.fork` (`lib/runtime/runner.ts:1226`) forwards `shared` to
  `runForkAll` as `shareGlobals`. `runBatch` has a batch-level
  `shareThreads` (`runBatch.ts:195`) used only by the tool loop
  (`promptRunner.ts:464`); `runInBranchAlsFrame` (`runBatch.ts:456`) picks
  `sharedView` or `forkBranchView` from it. `forkBranchView` deep-clones
  the active thread's messages into a new subthread when the branch starts
  and emits a `threadCreated` event.
- Locals are shared by reference between arms: the fork body reads the
  parent frame through its closure. The side arm evaluates its call's
  receiver, callee, and arguments inside its first step, after several
  awaits, so a write to the same local in the main arm's first statements
  can land first.
- `runBatch` in `"all"` mode is `allSettled`: an interrupt from one arm
  surfaces only once every sibling has settled. A JS error thrown by one
  arm is rethrown and the siblings' interrupts are dropped. `RestoreSignal`
  thrown inside an arm leaves through that path; the run loop restores and
  re-enters the fork step, which re-invokes any branch with no cached
  result while the first invocation's promise is still in flight.
- `runForkAll` installs one decision collector per block
  (`docs/dev/llm/decision-models.md`); under a decision-model provider the
  calls of all arms share rounds.
- `docs/dev/runtime/pause.md`: an external pause cannot land on a branch
  stack and waits for the join. `docs/dev/cli/debugger.md`: the debugger
  stops inside branches, but `set` is refused there.
- Test fixtures: `tests/agency/<dir>/<name>.agency` with `<name>.test.json`
  (`llmMocks`, `interruptHandlers`), run with
  `node dist/scripts/agency.js test tests/agency/<dir>`. A fixture is
  compiled from source; nothing can set an AST field on it.
  JavaScript-driven tests live in `tests/agency-js/<name>/` with
  `agent.agency`, `test.js`, `fixture.json`, run with
  `node dist/scripts/agency.js test js <dir>`. `__setLLMClient` from the
  compiled module installs a mock client; see
  `tests/agency-js/resume-events-in-span/test.js`.
- Build: `make build`, then `make stdlib` and `make agents` in a fresh
  worktree. `pnpm run typecheck` covers tests. `pnpm run fmt:ts` before
  pushing.
- Observed while spiking, not caused by it: `make stdlib` reports two
  AG2009 errors at `stdlib/index.agency:704` and `:708` on a clean build
  of main's source, and `tests/agency/fork/llm-tools/tool-multi-cycle`
  fails in a fresh worktree with a missing module. Both pass or are silent
  in the main checkout's older `dist`. Fix or track both before Task 0,
  or its verification cannot be trusted.

## Global constraints

- `async` adds no runtime semantics beyond the two changes in Tasks 0 and
  0b. Everything else it does is what the equivalent `parallel` block does.
- The lowering runs before `parallelDesugar` and produces an ordinary
  `parallelBlock` node, so every existing parallel test applies to its
  output. It clears the `async` flag, so the old builder paths never see
  a flagged call again; they are deleted in Task 5.
- The lowering never rewrites statements inside the arm. Returns are
  decided at the join (Task 2 step 4).
- Every walk the lowering does over user code goes through a slot table
  (`bodySlots`, `expressionSlots`, `identifierSlots`), never a hand-written
  switch over node types.
- Error messages name the construct the user wrote (`async`), not the
  lowered form, and every async error is reported by the typechecker so the
  editor and `agency tc` show it (Task 3).
- `mainThread` is not user-facing syntax. Only the lowering sets it.

## Task 0b: a handler applies only inside the branch that registered it

Today a `handle { } with approve` live in one fork arm approves interrupts
raised in a sibling arm, because the chain is one list per run. So does a
`preapprove()`d function, which pushes an approve-everything handler for
the duration of each call. With `async`, the reply is one arm and the side
call is the other, so a side call that wraps itself in `with approve`, or
is preapproved, approves the reply's `std::write` prompts for as long as it
runs. The same leak exists today between two tool calls in one model
round. This must land before Task 2, and Task 6 must not be done without
it.

1. `lib/runtime/types.ts`: `HandlerEntry` gains `stack: StateStack | null`,
   the stack that registered it. `null` means "applies everywhere". The
   field and the `pushRunHandler` parameter below are required, not
   optional, so a registration path added later has to say which it is
   instead of widening its reach by forgetting an argument. Only two
   registrations pass `null`, because they have no runner stack: the
   `--policy` handler and the global-init wrapper.
2. Record the stack on every other path:
   - `lib/runtime/state/context.ts`: `pushRunHandler(fn, liveGuardIds,
     stack)` stores it. `Runner.handle` passes `this.stack`; the `with`
     modifier's runner path goes through `Runner.handle` already.
   - `withPushedHandler` (`asyncContext.ts:401`) takes the stack and
     passes it on. `AgencyFunction.preapprove()` passes `run.stack` from
     the wrapped body. `agency.withHandler` (`agency.ts:294`) passes
     `currentRun().stack`. When either is registered at the root, the root
     stack is an ancestor of every branch, so its reach does not change.
3. `lib/runtime/interrupts.ts`, `runHandlerChain`: skip an entry only when
   its stack and the raising stack sit in separate subtrees. That is: the
   entry's stack is set, is neither the raising stack nor an ancestor of
   it, AND the raising stack is not an ancestor of the entry's stack.
   Ancestry is one method on `StateStack`, `isWithin(other)`, written
   next to `branchPath()` and walking `parent` the same way;
   `runHandlerChain` calls it twice and holds no walk of its own. The
   second condition is what makes the rule fail closed: if some raise
   path ever passes an ancestor stack instead of the branch it runs on,
   the branch's own handlers are still consulted, as they are today,
   instead of being skipped. Sibling arms are still isolated from each
   other, since neither is an ancestor of the other. A raiser can only be
   an ancestor of a live handler's stack through a bug, because a parent
   stack is suspended while its branches run, so the condition costs
   nothing. The skip is silent, like the `eligible` filter: no invocation,
   no statelog decision.
4. Confirm each caller of the chain passes the stack it runs on, and say
   so in a comment at the top of `runHandlerChain`: the generated
   templates (`run.stack`, the branch stack inside an arm),
   `agencyInterrupt.ts:202`, `guardTripInterrupt.ts:148`, and `ipc.ts:715`
   (the stack `_run` was called on, an ancestor of everything the child
   does). Confirm the two paths that rebuild state still agree: a resume
   replays `Runner.handle` on the resumed branch's stack, so the recorded
   stack is the live one, and `parent` is set on every branch entry
   (`runBatch.ts:326`) before any code runs, including after a resume.
5. Tests. `tests/agency-js/handler-fork-isolation` changes from "each tag
   ASKED exactly once by the sibling" to two assertions: no cross-arm
   asks, and each arm's own handler still answers its own raise, so the
   test fails if the skip turns everything off. New fixtures under
   `tests/agency/fork/handlers/`: `sibling-approve-does-not-apply` (arm A
   has `with approve`, arm B raises with no other handler, the interrupt
   reaches the host), `sibling-preapprove-does-not-apply` (a preapproved
   function runs in arm A, arm B's raise reaches the host),
   `enclosing-handler-still-applies` (a `handle` around the fork answers
   both arms), `root-policy-still-applies` (`--policy` rejects inside an
   arm), `ts-raise-in-arm-rejected` (a helper raises through
   `agencyInterrupt.ts` inside an arm, a `with reject` sits in the same
   arm, the raise is rejected). A `tests/agency/subprocess/` case where
   the parent's handler inside a fork arm answers the child's forwarded
   interrupt from that arm.
6. Docs and changelog: `docs/dev/runtime/concurrent-interrupts.md` "Known
   limitations" loses the sharing note; `docs/site/guide/handlers.md`
   gains a sentence that a handler inside a branch applies to that branch

   in one `llm()` round no longer share handlers, so a prompt that a
   sibling tool's handler used to approve silently now reaches the user,
   including in `agency agent`.

## Task 1: narrow the `async` parser

The flag, the reserved word, and the formatter already exist. This task
restricts where the keyword is accepted.

1. `parsers.ts`: keep the flag set at exactly two positions, `async <call>`
   as a statement and `let|const x[: T] = async <call>`. The two places
   that accept and discard the keyword (`parsers.ts:4930`, `:5907`) and
   any expression-position acceptance in `asyncValueAccessParser`
   (`:3669`) become a parse error that says `async` is a statement or the
   right-hand side of a declaration. A `with` suffix stays what it is
   today: a `withModifier` wrapping the statement.
2. A tripwire in the builder: if a call with the flag reaches codegen,
   throw. The lowering clears it, so the old `pendingPromises.add` path is
   unreachable from this task on.
3. Tests: parser unit tests for both forms, the `with` suffix, and the
   expression-position error; a formatter round-trip, which should already
   pass.

## Task 2: the lowering

A new pass in `lib/preprocessors/asyncDesugar.ts`, called from
`typescriptPreprocessor.ts` just before `desugarParallelBlocks`, applied to
every statement list reached through `bodySlots` (function and node bodies
and, recursively, `if` branches, loop bodies, `handle` bodies, `seq` arms,
block arguments, finalize bodies). The body of a `parallel` block is a list
of arms, not a statement sequence, so the pass does not treat it as one; an
`async` directly there is refused (Task 3). The checks in step 2 are also
run by the typechecker (Task 3); the lowering asserts they passed rather
than reporting them again.

For each statement list, **from the first `async` to the last**, lowering
each call's arm recursively after it is formed. First to last is what gives
the overlap the feature exists for. Take the BMO shape:

```agency
let name = async nameConversation(msg)
let facts = async extractMemories(msg)
const reply = llm(msg)
saveTitle(name)
saveFacts(facts)
```

`name` joins at `saveTitle`, so its arm is `[async extractMemories, reply]`;
lowering that arm, `facts` is unused inside it, so its join is the end of
the arm. The result is `nameConversation ‖ (extractMemories ‖ reply)`.
Last to first would form `facts`'s block first, `saveTitle(name)` would sit
inside it, `name`'s arm would be empty, and `nameConversation` would run
alone before anything else. The hoists compose in the first-to-last order:
`facts` is hoisted out of the inner block into the outer arm, and
`collectBindings` carries it out of the outer block because it descends
into `parallelBlock` bodies.

1. **Find the join.** For the binding form, the index of the first later
   statement that mentions the name anywhere, found by walking the
   statement with `walkNodes` and reading `identifierSlots` at each node,
   so that `with` statements, `match` arms, casts, interrupts, and every
   node kind added later are covered. Check whether `identifierSlots`
   reports an assignment's left-hand side; an assignment to the name counts
   as a use. For the statement form, the end of the list. In both forms, if
   the join would fall after a top-level `goto`, `break`, or `continue` in
   the list, the join moves to just before the first of them, so a node
   that ends in `goto` and a loop body that ends in `continue` can still
   use the statement form. Replace `collectReferences` in the cross-arm
   check with the same walk, which closes the same hole for hand-written
   `parallel` blocks.
2. **Check the arm.** The statements between the `async` and the join
   become the `seq` arm. Refuse a `goto`, `break`, or `continue` inside the
   arm that is not inside a loop that itself sits inside the arm (nested
   ones below the top level are what step 1 does not rescue). Refuse
   `async` with no enclosing function or node, at global initialization,
   inside a handler function body, inside a callback body, and as a direct
   arm of a `parallel` block. Refuse `?` on the async call itself
   (`let x = async f()?`): the hoist pass would lower it inside the side
   arm, the side arm's value would be the failure, and the join check only
   looks at the main arm. A `return` is never refused.
3. **Snapshot what the side call reads.** Hoist every expression slot of
   the call node, as `expressionSlots` lists them (the receiver of a method
   call such as `async notes.summarize(x)`, and each argument), into a
   `const __async_arg_n = <expr>` before the block, and the callee name
   too when it resolves to a local (`async handler(x)`), so the side call
   reads what a plain call at that line would have read and nothing the
   main arm rebinds can race it. Objects stay aliased, as for any call.
   Named arguments and splats are hoisted the same way; a block argument
   stays where it is. A call in an argument therefore runs before the
   overlap: `async f(g())` evaluates `g()` first, as a plain call would.
   Once everything is snapshotted the side arm references only
   temporaries, so the cross-arm check cannot fire on an async block.
4. **Decide returns at the join, in `desugarOneParallel`.** Do not walk or
   rewrite returns. The lowering sets `origin: "async"` on the
   `parallelBlock` and emits nothing after it. For such a block
   `desugarOneParallel` does two extra things: it ends the main arm with
   `return __asyncDone({ bindings })` instead of the plain bindings
   object, and it pushes the join check between
   `letAssign(armsVar, fork)` and the hoist loop:

   ```agency
   if (!__asyncFinished(__arms_n[1])) {
     return __arms_n[1]
   }
   ```

   It has to be there, because only `desugarOneParallel` knows the
   `__arms_n` name, and the hoists must not run before the check.
   `__asyncDone` and `__asyncFinished` are one pair of runtime helpers
   exported from `lib/runtime/`: the first builds the marked object, the
   second recognises it. Generated code never spells the marker's shape,
   so the key lives in one file. The test side cannot be inlined anyway:
   a value can be `undefined` for a bare `return`, a failure from `?` or
   from an interrupt rejected directly in the arm, or any user value, so
   generated code must not read a property off it. This covers user
   returns at any depth, the returns the hoist pass creates later for
   `?`, `return` with no value, and rejection in the arm, with no
   knowledge of closure boundaries. In a node the same check returns the
   node's result.
5. **Emit.** `parallel(shared: true) { <side arm> seq { <arm statements> } }`
   with `origin: "async"` set on the node, preceded by the snapshot
   temps, and with the `async` flag cleared on the call. For the binding
   form the side arm is `let x = <call>` so the existing hoisting puts `x`
   in scope after the block. If the side call carries a `with` suffix, the
   side arm is `seq { let x = <call> with approve }`, because
   `withModifier` is not in `ALLOWED_ARM_TYPES`.
6. **No user-facing errors from the desugar.** The lowering builds both
   arms itself, from allowed shapes, and after step 3 the side arm reads
   only temporaries, so neither the allowlist check nor the cross-arm
   check can fire on an `origin: "async"` block. If one does, that is a
   bug in the lowering: `desugarOneParallel` throws an internal error
   naming `async` rather than wording a message for a case the user cannot
   reach.
7. **Empty arm.** An `async` followed immediately by its first use, or at
   the end of a block, has an empty `seq` arm. Emit the side call alone, as
   a plain call, since there is nothing to overlap with.
8. **The old tests.** With the lowering in place, `tests/agency-js/async/*`,

## Spec edits

The spec needs these changes to match this plan:

- The keyword is `async`, not `spawn`, throughout, with the reasoning
  from the top of this plan in "The decision". The "Out of scope" line
  about removing `async` becomes "deleting the old `async` runtime".
- "Semantics to document for users": replace "A side call that should
  never ask wraps itself in `handle { } with approve` or `with reject`"
  with the Task 0b rule, and add the bullets from Task 4 step 1.
- "Where the join is": add the move before a trailing `goto`, `break`, or
  `continue`, and say async calls lower first to last, which is what "The
  second spawn's join is bounded by the first spawn's arm" already means.
- "Lowering": the side call's receiver, callee, and arguments are hoisted
  before the block; returns are decided at the join, not rewritten; the
  lowered example gains the marked completion and the join check; and
  `mainThread: 1` appears there as a field the lowering sets on the node,
  not as something a user can type.
- "Compile errors": the loop rule becomes "a `break` or `continue` nested
  inside the arm below the top level"; `goto` likewise; add the callback
  body, an `async` as a direct arm of `parallel`, and `?` on the async
  call. An `async` in a loop body is otherwise allowed, and each iteration
  joins at the end of its body.
- "Out of scope": note that an external pause waits for the join, as a
  consequence of #1046.
