# The Agency Agent as a Stdlib Function: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Users can call the Agency agent as `agencyAgent(...)` from `std::agents/agency`, and `agency agent` becomes a caller of that function.

**Architecture:** The three brains move from `lib/agents/agency-agent/brains/` to `stdlib/agents/brains/`. Each brain takes its settings as parameters and reads no module-level state from the CLI. The CLI keeps the REPL, sessions, settings, policy, and the reads of the user's own files, and passes their results in through `context` and `extraTools`.

**Tech Stack:** Agency (`.agency` files in `stdlib/` and `lib/agents/`), TypeScript helpers in `lib/stdlib/`, Agency tests (`*.agency` with a `*.test.json` beside it), vitest for the TypeScript helpers.

**Spec:** `docs/superpowers/specs/2026-11-14-agency-agent-stdlib-design.md`. Read it before starting. This plan does not repeat its reasoning.

Three facts about the code that are easy to miss:

- **A `static const` runs once per process, when its module loads.** A plain top-level `let` or `const` is set up again for every run. `docs/site/guide/global-vs-static.md` explains this. The stdlib brains may use statics only for files packaged with Agency.
- **Every module in the import closure runs its statics at startup**, whether or not anything in it is called. A static in a stdlib module that reads the user's files would run for every program that imports it.
- **A tool's bound parameters are hidden from the model.** `someTool.partial(name: value)` returns a tool whose schema omits `name`. The coordinator already uses this for `elapsedTime.partial(since: turnStart)`.

## How to test

Tests in this repository are slow. Follow these rules for every part.

- Make all the changes of a part first. Then run `make` once. Then run that part's tests once.
- Save every test run's output to a file under the scratch folder, and read the file if something fails. Do not rerun a test to see its output again.
- Run only the tests listed for the part. Do not run `pnpm run test:agents` or the whole `tests/agency` suite locally. CI runs them on the pull request.
- Run Agency tests with `--check-capabilities`, as CI does:

```
pnpm run agency test --check-capabilities <file.agency> > <scratch>/<name>.log 2>&1
```

- Run `pnpm run typecheck` after every TypeScript edit. Do not run bare `tsc`.
- Run `pnpm run lint:structure` once per part.
- Before pushing a part, read its diff against `docs/dev/contributing/anti-patterns.md`.
- Push only when the part's tests exit with code 0.

## Review Focus

1. **A library user calls `agencyAgent` twice from code on one thread.** They expect one system prompt in the thread, with the second call seeing the first call's messages. Pinned by Task 3.4, test `secondCallSeesFirst`.
2. **A model calls `agencyAgent` as a tool.** They expect the call to start on an empty thread and return a `Result`. Pinned by Task 3.4, test `asToolStartsFresh`.
3. **A caller's handler rejects a write the agent attempts.** They expect the rejection to hold even though the agent's own code approves packaged reads. Pinned by Task 3.4, test `callerHandlerRejects`.
4. **A bundled prompt file is missing from the install.** They expect a failure value, with the process still running. Pinned by Task 3.2, test `missingPromptIsFailure`.
5. **A long REPL session is compacted, then saved, then resumed.** They expect the resumed transcript and the next turn to use the compacted conversation. Pinned by Task 2.1 and Task 2.3.
